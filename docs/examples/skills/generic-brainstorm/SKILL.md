# Generic Brainstorm Skill

这是一个不绑定具体领域的头脑风暴方法论。它可以配合 `@generic-brainstorm` subagent 使用，也可以由主 Agent 直接执行。

---

## 核心原则

1. **先框定，再发散**：不清楚问题边界时，优先重述问题和成功标准。
2. **先独立，再讨论**：角色先独立提出观点，避免过早收敛。
3. **先评分，再决议**：用统一维度比较方案，避免只凭直觉选择。
4. **先验证，再投入**：高不确定性方案必须配套低成本验证动作。
5. **保留反方意见**：最终决议必须记录主要反对理由和改道条件。

---

## 触发条件

当出现以下任一情况时使用：

- 连续尝试无进展，需要新思路
- 方案太多，难以取舍
- 决策影响大，需要评估风险
- 团队意见分散，需要形成共识
- 问题定义模糊，需要重新框定
- 需要把讨论转成行动清单

---

## 深度等级

| 等级 | 适用场景 | 时间成本 | 角色数 | 输出粒度 |
|------|----------|----------|--------|----------|
| **quick** | 快速破局、日常小问题 | 低 | 3 | 直接建议 + 低成本动作 |
| **standard** | 常规决策和方案比较 | 中 | 4-6 | 评分矩阵 + 推荐方案 |
| **deep** | 高复杂度或高风险问题 | 高 | 6-8 | 多轮讨论 + 风险审计 + 改道条件 |
| **council** | 战略级、组织级、不可逆决策 | 很高 | 8-10 | 正反辩论 + 决议记录 + 复盘标准 |

默认使用 `standard`。如果满足以下任一条件，自动升级到 `deep`：

- 决策不可逆或回滚成本高
- 涉及安全、合规、隐私、伦理或重大财务风险
- 输入信息互相冲突
- 方案之间存在长期结构性取舍

## 推荐角色组合

### 通用最小组合（quick）

- **目标澄清者**：确认真正要解决的问题
- **实践执行者**：提出最快可执行路径
- **反方辩手**：指出假设漏洞

### 标准组合（standard）

- **目标澄清者**
- **系统思考者**
- **实践执行者**
- **风险审计员**
- **创新发散者**
- **证据主义者**

### 深度组合（deep）

- **目标澄清者**
- **系统思考者**
- **第一性原理分析师**
- **实践执行者**
- **风险审计员**
- **反方辩手**
- **证据主义者**
- **决策主持人**

### 最高级组合（council）

在 `deep` 基础上增加：

- **经济评估者**
- **伦理与边界守门人**
- **长期维护者**
- **用户/受众代表**

按问题裁剪，不必机械使用全部角色。

## 标准流程

### 1. 输入整理

整理以下信息：

```markdown
- 问题：
- 目标：
- 背景事实：
- 约束：
- 已尝试方案：
- 已知失败原因：
- 偏好权重：速度 / 质量 / 成本 / 风险 / 创新 / 可解释性
- 期望深度：quick / standard / deep / council
```

如果用户没有指定深度，按风险和复杂度选择。

### 2. 问题重定义

输出：

```markdown
原始问题：...
重定义后的核心问题：...
成功标准：...
当前最大不确定性：...
```

如果原始问题明显偏离目标，应直接指出，并给出更好的问题表述。

### 3. 多角色发散

每个角色独立输出：

```markdown
## {角色名}

### 核心判断
- ...

### 候选方案 / 观察
- ...

### 主要风险或盲区
- ...

### 建议验证动作
- ...
```

### 4. 讨论与挑战

至少包含：

- 哪些方案互相冲突
- 哪些假设最脆弱
- 哪些方案可以组合
- 哪些方案应该删除
- 哪个低成本实验能最快减少不确定性

### 5. 评分排序

默认评分维度：

| 维度 | 权重 | 说明 |
|------|------|------|
| Impact | 25% | 成功后影响多大 |
| Feasibility | 20% | 当前是否可行 |
| Confidence | 15% | 证据是否充分 |
| Speed | 15% | 多快能验证或见效 |
| Risk | 15% | 分数越高风险越低 |
| Learning | 10% | 失败后是否仍有学习价值 |

总分：

```text
Impact * 0.25 + Feasibility * 0.20 + Confidence * 0.15 + Speed * 0.15 + Risk * 0.15 + Learning * 0.10
```

如用户明确偏好，调整权重并说明理由。例如：

- 赶时间：提高 Speed 和 Feasibility
- 高风险：提高 Risk 和 Confidence
- 探索创新：提高 Impact 和 Learning
- 成本敏感：提高 Feasibility，降低高投入方案排名

### 6. 决议记录

最终输出必须包含：

```markdown
## 决议

- 推荐方案：
- 选择理由：
- 备选方案：
- 暂不采用方案：
- 决策置信度：高 / 中 / 低
- 最大风险：
- 最小验证动作：
- 改道条件：
```

### 7. 行动清单

```markdown
| 优先级 | 动作 | 目标 | 验证方式 | 截止/触发条件 |
|--------|------|------|----------|---------------|
| P0 | ... | ... | ... | ... |
| P1 | ... | ... | ... | ... |
```

## 质量检查

完成前检查：

- 是否明确重定义了问题
- 是否至少提出 3 个候选方向
- 是否包含反方挑战
- 是否有评分矩阵
- 是否有明确推荐和不推荐方案
- 是否给出最小验证动作
- 是否列出改道条件
